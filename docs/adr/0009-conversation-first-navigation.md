# 0009 — Conversation-first navigation(rail 退役,messenger 形态)

## Status

Accepted (2026-09-07). Planned implementation in three cuts: #368
(刀 1:rail 退役、滑出菜单、会话列表分区、看板常驻入口)→
#369(刀 2:二级面统一全屏接管、peek 抽屉机制退役)→
#370(刀 3:移动端单列表对齐)。

## Context

桌面端左侧是一条 72px 图标工具栏(Rail),owner + devtools 全开后平铺
**13 个入口**:对话、收件箱、私聊、观测、交付、看板、日历、文档、项目、
技能库、智能体、人事、我(外加头像与退出,「我」实际双入口)。问题有三:

- **无层级**:每天用的(对话/收件箱)和一周碰一次的配置面(技能库/人事)
  视觉权重完全一样;
- **溢出隐患**:rail 无滚动,13 按钮 + 头像 + 退出约需 780px 高度,矮窗口
  即裁切,退出键不可达;
- **工具感**:形态读作"多视图工作台",而非用户想要的"聊天软件"。

用户 2026-09-07 提出"产品更像一个聊天软件",经 grilling 八题定案 +
HTML 原型三轮试用迭代(`design-preview/chat-first-nav.html`,终态经用户
确认)。三轮迭代里被否掉的中间形态记录在 Rejected alternatives——尤其
是"右抽屉"形态两轮试用均被否:二级内容呈现为挂在聊天旁的 440px 窄侧板,
"重点不明确",没有"我打开了日历"的主场感。

## Decision

1. **范围 = 布局去工具感(A 层)**。事件流入对话(B:卡片/交付/HR 提案
   以消息出现)与消息内办事(C:审批按钮)明确**推迟**,不是否决——
   留作未来方向。B 落地前,CONTEXT.md 中 HR Agent"从不在对话中汇报"
   词条不受冲击。
2. **形态 = Telegram 式纯 messenger**。应用本体 = 会话列表 + 聊天两栏;
   rail 整体退役。参照系选 Telegram(纯 DM 列表)而非 Slack(工作聊天+
   集成事件)或 Discord(多服务器):本产品单 Team、以对话为工作主轴,
   纯 messenger 的"一切都在列表里"哲学成立,且与"嫌入口多"同解。
3. **收件箱退役 → 列表分区**。会话列表顶部常驻「需要你行动」高优分区
   (action_required + attention;info 不进,沿用现收件箱徽标语义),
   分区头带聚合徽标、可折叠;InboxView 退役,inbox store 保留供分区消费。
4. **私聊退役 → 列表分区**。WhispersView 退役;纯 agent 会话以「Agent
   对话」分区并入会话列表(owner 闸,非 owner 不可见整分区),数据源
   `/peek/agent-chats` 不变。CONTEXT.md Whisper 词条随刀 1 改写为分区形态。
5. **一键可达底线 = 看板独享**。标题栏常驻按钮 + B 快捷键——它是工作
   分派现场,使用频率与聊天同档;其余九面(日历/文档/项目/交付/智能体/
   技能库/人事/观测/我)全部收进滑出菜单。
6. **滑出菜单 = 全高左侧滑出层**(非侧栏角落浮卡):头像行(→ 我,
   单一入口,daemonOutdated 金点随行)→ 工作面组(日历/文档/项目/交付)
   → 公司组(智能体/技能库/人事/观测;紧凑弱化,与工作面拉开层级)
   → 退出钉底。权限闸(h owner/admin、observability devtools)随菜单项
   显隐,语义与 rail 时代一致。
7. **二级面统一全屏接管**(含看板,同构):菜单 = 启动器,点谁谁接管
   整个内容区,左上「‹ 返回对话」回聊天。聊天右槽的**产物类 peek 抽屉**
   (文档/看板/日历 peek)退役,聊天内卡片改开全屏视图;ThreadDrawer/
   InfoPane(聊天侧信息面,非导航面)保留。
8. **三刀纵切**:刀 1 导航重构(#368,不碰视图内部)→ 刀 2 全屏壳 +
   peek 拆除(#369)→ 刀 3 移动端对齐(#370,MobileTabBar 单列表化)。

## Consequences

- **一级面 = 对话 + 看板**;列表分区给出第二层结构(行动 > 频道 > 私信 >
  Agent 对话),13 入口的层级与溢出问题同时消解。
- **打开二级面 = 换场,不再是贴边小窗**:焦点明确;代价是离开聊天上下文,
  由统一返回键兜底(返回恢复选中会话)。
- **产物 peek 退役**:聊天中点文档卡从"贴着聊天展开"变为"全屏打开",
  多一次返回;这是用户在原型试用中亲自选择的取舍。
- **移动端在刀 3 之前与桌面形态分叉**(MobileTabBar 仍是旧形态),属
  已知欠账。
- `ViewKey` 清理顺车完成:`library` 在**桌面侧**是死键(无渲染分支、无 rail
  入口,刀 1 无需动作);但移动端 `MobileTabBar` 仍是活消费方(MobileLibrary),
  union 成员的最终移除随刀 3 落地。`convene` 上下文进入不受影响。
- 命令面板(⌘K 式中央搜索)本轮不做,记余量——与滑出菜单不冲突,
  可作未来加速器。
- 原型 `design-preview/chat-first-nav.html` 入库为形态基准(设计资产,
  非产品代码;后续实现以它对照验收)。

Rejected alternatives:**分组分隔线方案**(13 入口原样,只加分隔线——
不解决溢出与层级);**公司 hub 二级导航**(rail 保留 + 二级页——工具感
残留);**瘦 rail 折中**(3–4 图标 + 收纳——半吊子);**二级面右抽屉化**
(第一轮共识,原型两轮试用被否——侧栏感、重点不明确);**主区替换**
(列表恒在、主区切换——看板自带三栏,塞入后拥挤,需例外打补丁);
**居中大浮层**(模态承重,尺寸受限);**命令面板为主导航**(键盘优先,
与鼠标流不符,体量也最重)。
